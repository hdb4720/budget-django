Now one issue I had to work through changed what we had discussed earlier in finalizing manager_context (that is before I moved sort/filter into manager_context):
You pointed out I did not have to "return row" as the calls using {row} would see the changes in child functions. This did not prove to be the case in manager_sort or manager_filter. 

Why would these functions not reflect the changes back to the parent but instead require an explict return?

I am sure it has to do with the fact that all of the previous calls involved 1 row at a time and not the whole [list] as sort and filter both require. Anyway I pass in the [manager] and return [manager] and I see the changes in the return.

I think I answered this one myself: when I call a function with {row} it is mutable and therefore changes in the child function are seen at the parent. Changes in [manager] list on the other hand are not mutable(???) and so I have to return the modified [manager] for the parent to get changes.
