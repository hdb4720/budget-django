## Objectives
Modify the current method of presenting the budget rows in the budget-manager. Currently I am looking at individual budgets with historical analysis. This cause a distortion of the history as presented since the budget category may be represented by more then one row in any selected period.

The individual budget rows are still a central piece of the budget manager, but an improved presentation mode the individual budget rows will be managed during CRUD and persistence modules. The presentation module will summarize the budgets to a single budget row per period.

The first change required in this implementation is to modify the build_budget.query:
    - Currently the query is:
        ````
        budgets = Budget.objects.filter(
        due_date__gte=period.start,
        due_date__lte=period.end,
        ).select_related("category", "account")
        ```

    - The required change will include all future budgets as well
        -Note: this is a change from my previous discussions. I was proposing that only Planned future budgets should be included, but I see value in presenting to the user all future budgets to increase awareness of future budgetary issues and concerns
    
    - The proposed change to build_budget.query:
        ````
        budgets = Budget.objects.filter(
        due_date__gte=period.start,
        ).select_related("category", "account")
        ```

- The substantial change to implement current and future budgets wil be in the build_manager. Here I will need to use the budgets.QuerySet in conjunction with the BudgetManagerRow.
    - Add BudgetManagerRow.period: will hold the periods.id that matches budget.due_date 
    - Add period lookup to build_manager
