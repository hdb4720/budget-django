Collections of objects

For QuerySets and lists, the Python and template patterns are nearly parallel.

Python
for item in context["manager"]:
    print(item.category)
    print(item.amount)
Template
{% for item in manager %}
    {{ item.category }}
    {{ item.amount }}
{% endfor %}

Likewise, for a QuerySet:

Python
for budget in context["budgets"]:
    print(budget.due_date)
    print(budget.amount)
Template
{% for budget in budgets %}
    {{ budget.due_date }}
    {{ budget.amount }}
{% endfor %}
Single objects

For one model object, Python uses dictionary lookup followed by attribute access.

Python
period = context["period"]

print(period.start)
print(period.end)
print(period.label)
Template
{{ period.start }}
{{ period.end }}
{{ period.label }}
Dictionaries with known keys

Python uses square brackets or .get():

selected = context["selected"]

period_id = selected["period_id"]
scheme_id = selected.get("scheme_id")

The template uses dot notation:

{{ selected.period_id }}
{{ selected.scheme_id }}

The template expression:

{{ selected.period_id }}

corresponds approximately to:

context["selected"]["period_id"]
Dictionaries when you want every key and value
Python
for key, value in context["actuals"].items():
    print(key, value)
Template
{% for key, value in actuals.items %}
    {{ key }}: {{ value }}
{% endfor %}

Remember that Django templates omit the parentheses:

actuals.items

rather than:

actuals.items()
Your details defaultdict

Because each dictionary value is itself a list of detail objects, it requires two levels.

Python
for grouping_key, detail_rows in context["details"].items():
    print(grouping_key)

    for detail in detail_rows:
        print(detail.category)
        print(detail.due_date)
        print(detail.amount)
Template
{% for grouping_key, detail_rows in details.items %}
    {{ grouping_key }}

    {% for detail in detail_rows %}
        {{ detail.category }}
        {{ detail.due_date }}
        {{ detail.amount }}
    {% endfor %}
{% endfor %}
Your manager list and nested details
Python
for row in context["manager"]:
    print(row.category)
    print(row.amount)

    for detail in row.details:
        print(detail.due_date)
        print(detail.amount)
Template
{% for row in manager %}
    {{ row.category }}
    {{ row.amount }}

    {% for detail in row.details %}
        {{ detail.due_date }}
        {{ detail.amount }}
    {% endfor %}
{% endfor %}
One important difference

Python can easily look up a dictionary value using a variable:

category_id = 132
actual = context["actuals"].get(category_id)

Standard Django template syntax does not directly support the equivalent of:

actuals[category_id]

Writing:

{{ actuals.category_id }}

looks for a literal key named "category_id"; it does not use the value stored in the template variable category_id.

That limitation is one reason your approach of assigning values such as actual, history, and details directly to each BudgetManagerRow is useful. The template can simply use:

{{ item.actual }}
{{ item.history }}

rather than trying to perform dictionary lookups using item.category_id.
